# go-legado-demo 书源配置说明

本文档按 `main.go` 当前代码实现整理，重点说明：

1. 书源怎么配置
2. 支持哪些规则（逐条列出）
3. 每类规则的实际例子
4. 可直接参考的完整书源案例

## 1. 书源文件位置与格式

- 文件名：`data-all.json`
- 位置：项目根目录（与 `main.go` 同级）
- 格式：JSON 数组（每个元素是一个书源）

最小可用条件：

1. `bookSourceName` 不能为空
2. `searchUrl` 不能为空

## 2. 书源字段说明

单个书源主要字段如下：

1. `bookSourceName`：书源名称
2. `bookSourceUrl`：站点根地址（用于拼接相对链接）
3. `bookSourceType`：书源类型（普通小说可用 `0`，漫画常用 `2`）
4. `searchUrl`：搜索地址模板
5. `ruleSearch`：搜索结果解析规则
6. `ruleBookInfo`：书籍详情解析规则
7. `ruleToc`：目录解析规则
8. `ruleContent`：正文解析规则

## 3. searchUrl 配置

### 3.1 占位符

支持：

1. `{{key}}`：搜索关键词（代码会自动做 URL 编码）
2. `{{page}}`：页码（当前固定替换为 `1`）

示例：

```txt
https://demo.com/search?wd={{key}}&page={{page}}
```

### 3.2 请求配置扩展（POST / Header）

还支持下面这种格式：`URL,JSON配置`

```txt
https://demo.com/api/search,{"method":"POST","body":"wd={{key}}","headers":{"X-Token":"abc"}}
```

支持项：

1. `method`：`GET` / `POST`
2. `body`：POST 请求体
3. `headers`：自定义请求头

## 4. 规则能力总览（按代码逐条列）

下面都来自 `main.go` 当前实现。

### 4.1 选择器入口

支持：

1. `@css:xxx`
2. `css:xxx`
3. 直接写 CSS（不加前缀也行）
4. `@xpath:xxx`
5. `@json:xxx`
6. JSONPath 风格：`$.a.b`、`$..name`

### 4.2 字段提取后缀（`@` 后缀）

支持：

1. `@text`：文本
2. `@textNodes`：首个节点文本
3. `@html`：innerHTML
4. `@href`：`href` 属性
5. `@src`：`src` 属性
6. `@data-src`：`data-src` 属性
7. `@data-xxx`：任意 data 属性
8. `@attr-xxx`：任意属性

示例：

```txt
@css:.book a@href
@css:.cover img@data-src
@css:.item@attr-title
```

### 4.3 逻辑规则（兜底 / 拼接）

支持：

1. `a || b`：前面为空时用后面（兜底）
2. `a && b`：按顺序拼接
3. `@text:xxx`：字面量文本（常用于 `&&` 拼接中间符号）

示例：

```txt
@css:.none@text || @css:.title@text
@css:.title@text && @text: - && @css:.author@text
```

### 4.4 清洗替换（`##` 语法）

语法：

```txt
主规则##正则##替换文本
```

示例：

```txt
@css:.price@text##[^\d\.]##
```

用途：把“￥128.50元”清成“128.50”。

### 4.5 正则提取（`@regex:`）

语法：

```txt
@regex:正则表达式
```

返回规则：

1. 有分组时，返回第一个分组
2. 无分组时，返回整段匹配

示例：

```txt
@regex:\d+
```

### 4.6 XPath（`@xpath:`）

示例：

```txt
@xpath://h1/text()
@xpath://img/@src
```

### 4.7 JavaScript 规则

支持两种：

1. `@js:...`
2. 旧格式 `<js>...</js>`（兼容）

`@js:` 可用变量/函数：

1. `source`
2. `result`
3. `trim(v)`
4. `replace(v, old, new)`（只替换一次）
5. `replaceAll(v, old, new)`
6. `split(v, sep)`
7. `join(arr, sep)`
8. `isEmpty(v)`

示例：

```txt
@js:trim(source)
@js:replaceAll(trim(source), "-", "_")
```

### 4.8 JSON 规则能力

支持：

1. `@json:$.book.title`
2. `$.book.title`
3. `$..name`（递归找 key）
4. `items[*].name`（数组遍历）
5. `items[1].name`（数组下标）
6. 裸字段名：`name`、`authorName`
7. 模板替换：`{{$.id}}`、`{id}`
8. 模板中 `&&` 拼接
9. `@put:{k:$..v}`（当前实现会忽略输出）

示例：

```txt
@json:$.book.title
items[1].name
https://api.demo.com/book/{{$.book_id}}
https://api.demo.com/chapter/{id}
```

### 4.9 CSS 扩展写法

支持：

1. `:contains(关键字)`
2. `li[1]`（0 基下标）
3. `:eq(n)` / `:gt(n)` / `:lt(n)`
4. `id.xxx` -> `#xxx`
5. `class.xxx` -> `.xxx`
6. `tag.div` -> `div`

示例：

```txt
@css:li:contains(第二章)@text
@css:li[1]@text
@css:.novel_info p:eq(0) a@text
```

## 5. 四段规则怎么配

### 5.1 `ruleSearch`（搜索）

字段：

1. `bookList`：搜索列表（HTML 节点规则或 JSON 路径）
2. `name`
3. `author`
4. `intro`
5. `bookUrl`

说明：当 `bookList` 像 JSON 规则（如 `$`、`@json:`、`data.`、`result.` 开头）时，会走 JSON 解析流程。

### 5.2 `ruleBookInfo`（详情）

字段：

1. `name`
2. `author`
3. `intro`
4. `coverUrl`
5. `tocUrl`

补充逻辑：

1. `name` 为空且响应里有 `"title"` 时，会尝试 `$..title`
2. 若 `ruleToc.chapterUrl` 包含 `@get:{comic_id}`，会尝试从详情 JSON 抽取 `$..comic_id`

### 5.3 `ruleToc`（目录）

字段：

1. `chapterList`
2. `chapterName`
3. `chapterUrl`

补充逻辑：

1. 同 URL 自动去重
2. 支持 `@get:{comic_id}` 占位替换

### 5.4 `ruleContent`（正文）

字段：

1. `content`

补充逻辑：

1. 普通源正文会做 HTML 清洗
2. `bookSourceType == 2`（漫画）不会做文本清洗（防止 `<img>` 被清掉）
3. 规则取不到时，会走内置兜底选择器（如 `.content`、`article`）

## 6. 案例一：HTML 站点

```json
{
  "bookSourceName": "示例小说源",
  "bookSourceUrl": "https://www.demo.com",
  "bookSourceType": 0,
  "searchUrl": "https://www.demo.com/search?wd={{key}}&page={{page}}",
  "ruleSearch": {
    "bookList": "@css:.search-list .book-item",
    "name": "@css:.title@text",
    "author": "@css:.author@text",
    "intro": "@css:.intro@text",
    "bookUrl": "@css:a@href"
  },
  "ruleBookInfo": {
    "name": "@css:h1@text",
    "author": "@css:.meta .author@text",
    "intro": "@css:.book-intro@text",
    "coverUrl": "@css:.cover img@src",
    "tocUrl": "@css:a.catalog@href"
  },
  "ruleToc": {
    "chapterList": "@css:.chapter-list li",
    "chapterName": "@css:a@text",
    "chapterUrl": "@css:a@href"
  },
  "ruleContent": {
    "content": "@css:#chapterContent@html"
  }
}
```

## 7. 案例二：JSON API 站点

```json
{
  "bookSourceName": "示例API源",
  "bookSourceUrl": "https://api.demo.com",
  "bookSourceType": 0,
  "searchUrl": "https://api.demo.com/search,{\"method\":\"POST\",\"body\":\"wd={{key}}\",\"headers\":{\"Content-Type\":\"application/x-www-form-urlencoded\"}}",
  "ruleSearch": {
    "bookList": "$.data.list[*]",
    "name": "name",
    "author": "authorName",
    "intro": "intro",
    "bookUrl": "https://api.demo.com/book/{{$.book_id}}"
  },
  "ruleBookInfo": {
    "name": "$.data.name",
    "author": "$.data.author",
    "intro": "$.data.intro",
    "coverUrl": "$.data.cover",
    "tocUrl": "https://api.demo.com/book/{book_id}/chapters"
  },
  "ruleToc": {
    "chapterList": "$.data.chapters[*]",
    "chapterName": "title",
    "chapterUrl": "https://api.demo.com/chapter/{id}"
  },
  "ruleContent": {
    "content": "$.data.content"
  }
}
```

注意：`searchUrl` 是“字符串里嵌 JSON”，所以里面双引号必须转义。

## 8. 常见问题

1. `bookSourceUrl` 没带协议，导致相对链接拼接错误
2. `bookUrl/chapterUrl` 是相对路径，但基地址写错
3. 实际返回 HTML，却按 JSON 规则解析（或反过来）
4. `##` 正则写错，把正文清空
5. 漫画源没设 `bookSourceType=2`，图片正文被清洗掉
6. `sourceIndex` 传错，调到了别的书源

## 9. 调试建议

搜索接口加 `debug=1`：

1. `GET /api/search?sourceIndex=0&key=凡人&debug=1`
2. 返回会包含 `parser`、`searchUrl`、`htmlPreview`、`resultCount`

另外程序会写 `debug_logs/YYYYMMDD/`，可以直接对比“原始响应”和“解析结果”定位问题。
